## 6. Known pitfalls

- **`f3d.o2r` on a rebuild.** Every build's POST_BUILD step copies the checkout-root `f3d.o2r` (`bf16e8dd…`, repackaged from `shaders/` by
  the build) over the registered one in `build-us/Release` (`73ab91ef…`). Never take runtime files from `build-us/Release` after a
  build. Pair a new executable with the lab import's registered files, and restore `build-us/Release` from the D: archive
  (`docs/rl_decisions_2026-11-04.md` §4).
- **The deferred rebuild** (decided 2026-11-05; the plan for the day is in §4 of the decisions doc, steps 1 to 8, with a tick-by-tick
  A/B against `30a3913b`). The native items that wait for it, none of them in the pinned executable:
  1. **The launch-nonce identity token** (`SSB64_RL_LAUNCH_NONCE`, `INFRA_2026-11-04.md` fix 2; the native code is already in the tree).
     Without it every launch is identity `unverified`, and `BATTLESHIP_REQUIRE_IDENTITY` must stay unset.
  2. **`SSB64_LOG_PATH`**, the per-process log (fix 2). The pinned executable ignores it and keeps the shared log.
  3. **About 20 trace fields (words) per tick:** the read-only `btt_state_v1` block of `STATE_MACHINE_CANDIDATES.md` §5.2:
     - motion flags 0, 2 and 3;
     - `is_expend_tornado`;
     - 8 `status_vars` words;
     - a pending exit hook;
     - the TransN rotation;
     - `vel_ground.x`;
     - `ignore_line_id`;
     - the active hitbox damage;
     - optionally, a status-change ring.

     The larger `btt_contact_v1` block of `GLITCH_CANDIDATES.md` §3.2 belongs here too. Both are sent in the transport reply, not in
     `ssb64.log`.

  A rebuild changes the executable that every lab result is pinned to, so it is the owner's decision.
- **Real-lab tests in a worktree need a shim.** A worktree has no decomp checkout. The four real-lab tests read the stage source through
  `m7g_fixture`, so they need a test-only `sitecustomize.py` on `PYTHONPATH` that points `m7g_fixture` at the main tree's stage source
  (decomp at the pinned `e4f0634`, clean). Use the shim **only** for those four tests: it breaks `unit_run3_manifest`'s copied-tree
  comparison. Rerun them in the main tree before a commit (session log §18.1).
- **CRLF in the docs.** `core.autocrlf` is on, so Git warns "LF will be replaced by CRLF". Working-tree docs and tests are LF. The Write
  tool once produced CRLF. After writing a file, `grep -c $'\r' <file>` should print 0.
- **Never switch branches or re-checkout files in the main tree; use worktrees.** Seven run 3 `rl/` files (`m8_rd3_select.py`,
  `m8_rd_archive.py`, `m8_rd_claims.py`, `m8_rd_rule.py`, `m8_rd_run.py`, `m8_rd_session.py`, `m8_rd_worker.py`) are CRLF on disk there
  while the index holds LF, and the run 3 manifest hashes the bytes on disk: a rewrite changes the frontier digest from `73cbde95` to
  `11ec3040` for the same content.
- **The shell tool.** Bash commands over about 8 KB are truncated, so write long scripts to a file. Give Python `C:/...` paths, not
  `/c/...`.
- **A whole-repository grep** (decomp, build directories) takes minutes and loads the machine. During a night, search `docs/`, `tools/`
  or `rl/` only.
- **A pre-existing failure:** `crossing_search_run2_tests.py real` fails at the run-1 lab-code pin since the `port_lease.py` merge. It
  predates run 3 and is not a run 3 defect.
