## Fix 1: a launcher can only talk to its own game (port race, review D3)

**The bug.**

- The M2 launcher probes a port, closes the probe and lets the child bind it.
- A second launcher that probes in that window launches on the same port too.
- Its child fails to bind but keeps running without a transport, like the native game.
- If that launcher connects first, it connects to the *other* launcher's game. Nothing in `status` let it notice.

`rl/infra_port_tests.py race_legacy` reproduces this deterministically on the fake game: B's step is served by A's process.
The same scenario against the unmodified `rl/battleship_process.py` of `cloud/2026-11-03` gives
`{"a_pid": 807, "b_pid": 808, "b_step_served_by_pid": 807, "cross_talk": true}` (run once in the cloud with a scratch copy of
the old file).

**The fix, two layers.**

1. **Exclusive leases** (`rl/port_lease.py`, new). A launcher hands a port to a child only while it holds a lease file,
   created with `O_CREAT | O_EXCL` in one machine-wide directory:
   - the directory is `$BATTLESHIP_PORT_LEASE_DIR`, else `<temp>/battleship_port_leases`;
   - two launchers, in any process, worker or tool, can never hold the same port;
   - the lease is released after the child is gone;
   - leases of dead launchers, or older than 24 h, are reclaimed.

   `LaunchConfig.lease_ports` defaults to `True`. Ports chosen by the OS (`port=None`) are leased too, through
   `allocate_leased_port`. The per-rank `PortCandidates` blocks still apply, and the lease sits on top of them.
2. **Launch-nonce handshake.** It also covers programs that don't use leases.
   - Every launch passes a fresh 128-bit `SSB64_RL_LAUNCH_NONCE` to its child.
   - The child's `status` echoes it as `launch_nonce`, with `pid`. Native: `rl_boot.cpp` and `rl_transport.cpp`, present only
     when the variable is set, so default replies are byte-identical to before.
   - The launcher's first request on a new connection is that `status`:
     - a different nonce means `EpisodeOutcome.IDENTITY_MISMATCH`, the socket is closed at once, and nothing is ever sent to the
       other game, whose own client then connects normally;
     - no nonce means an executable that predates the field. It is accepted as identity `unverified`, unless
       `BATTLESHIP_REQUIRE_IDENTITY=1` or `LaunchConfig.require_identity=True` is set, in which case it is refused.
   - `diagnostics()` now reports `launch_nonce`, `identity`, `peer_pid` and `port_lease`.

**Compatibility.**

- The currently pinned executable (`30a3913b…`) has no nonce support, so every launch with it reports identity `unverified`
  and works as before. Only the lease layer protects it.
- Set `BATTLESHIP_REQUIRE_IDENTITY=1` for lab runs once an executable with this change is built, archived and pinned.
- The new `EpisodeOutcome` value is not mapped exhaustively anywhere (checked by grep), and standby launch attempts retry it
  like any startup failure.
- **Lab guard.** Lab processes run under `rl/frs_guard.LabGuard`, which refuses, and records as a violation, every write
  outside the lab root. With the guard installed, the lease directory is therefore `<lab root>/port_leases`, unless the variable
  already points inside the lab root. `port_lease.py` looks the guard up in `sys.modules`, so no lab file was edited.
  - This was found while writing the D4 harness; the first fix-1 commit did not have it. Without it, every lab launch would have
    failed and invalidated the run.
  - Test `lease_inside_lab_guard`: arms the real guard in a child process and asserts no violation. It fails on the first fix-1
    commit and passes on the follow-up.
- Fake-game additions are all opt-in (`FAKEGAME_LEGACY`, `FAKEGAME_BIND_DELAY_S`, `FAKEGAME_REACCEPT`,
  `FAKEGAME_LOG_REQUESTS`). A failed bind no longer crashes the fake: it stays alive without a transport, like the native game.

## Fix 2: every game process writes its own log, and native error lines are kept (review D8)

**The bug.**

- Every BattleShip process opens `%APPDATA%\BattleShip\ssb64.log` with truncation (`port/port.cpp` `main()`,
  `port/port_log.c`).
- With five workers plus standbys, each boot erases the others' lines.
- So the native-only warnings never survive a lab run: the fallback park, the multi-frame step, a transport bind failure.
- `port_log` also buffers, so lines still in the buffer are lost when the launcher terminates the process.

`rl/infra_log_tests.py shared_log_legacy` reproduces this on the fake game: A logs a native `ERROR` line, B boots, and A's line
is gone.

**The fix.**

- **Native.**
  - `main()` honours `SSB64_LOG_PATH`: a non-empty value is this process's own log file. Unset keeps the shared path exactly as
    before.
  - With a per-process log, `port_log` flushes every `SSB64 RL…` line and every line whose format contains `ERROR` or `FATAL`
    (`port_log_set_flush_important`).
  - Other lines stay buffered. Flushing every line was removed on purpose once, because it cost seconds per frame in a
    pathological case (see the comment in `port_log.c`; the header's "immediate fflush" sentence was already inaccurate).
- **Launcher** (`rl/battleship_process.py`):
  - Every episode gets `<episode dir>/ssb64.log` (`EpisodePaths.native_log_path`) and passes it as `SSB64_LOG_PATH`.
  - An inherited value is dropped. An explicit `extra_env` value wins, so an empty string keeps the old shared log.
  - Once the child is gone (in `finish()` and `close()`), the log's flagged lines (`ERROR`, `FATAL`, `not yet consumed`,
    `parking the game coroutine`) are kept in `episode.native_log_flags` and in `diagnostics()`.
  - With `BATTLESHIP_NATIVE_LOG_SINK_DIR` set, they are also appended to `<dir>/native_errors_<launcher pid>.jsonl`. That is one
    file per launcher process, so writers never interleave; each row carries the child pid, port and launch nonce. It outlives the
    episode directories, which the lab workers delete after each job.
  - Failing jobs keep their episode directory, and the log with it.
- **Opt-out:** `rl/m6_raphnet_bypass_regression.py` reads the shared log one process at a time, so it now passes
  `SSB64_LOG_PATH=""`. The direct-launch native-replay tools (`m7f_trace.native_tas_replay`, `m7g_equivalence`, `m7_smoke`)
  strip or never set the variable, so they are unaffected.
- **Fake game:** a native-like port log, opt-in. `SSB64_LOG_PATH`, or a truncated shared `$FAKEGAME_PREF_DIR/ssb64.log`;
  `FAKEGAME_NATIVE_ERROR_AT_STEP` writes an error line.

**Compatibility.** The pinned executable ignores `SSB64_LOG_PATH`: it keeps writing the shared log, and `native_log_flags` is
empty because no per-episode file exists. Everything else works as before.
